本文是作者和其他 Agent 的内容接口说明。维护内容时直接修改下列源文件，无须编辑生成的数据或页面脚本。

## 2. 小说章节接口

本次从当前主稿拆出 001—030 共三十章，正文逐段保持一致。后续可直接添加 031、032 等，无固定章数限制。

文件示例：`各章节/Melquiades-Ballad_031.md`

```markdown
# 第三十一章

第一段小说正文。

【场景或时间标记】

下一段正文。
```

- 文件名大小写和连字符须精确匹配 `Melquiades-Ballad_数字.md`；编号是至少三位的正整数，001、031、100、1000 均可。001 与 0001 属于重复编号，会报错。
- 仅扫描 `各章节/` 第一层 `.md`。忽略 DOCX、`README.md` 和以下划线开头的文件；其他不合命名规则的 Markdown 会停止构建并标明路径。
- 按编号数值升序排列，允许跳号。前后章跳转采用实际存在的相邻条目，不使用“编号加减一”。编号同时决定网址，例如 031 对应 `#/read/31`；不要为调整顺序随意重编号，以免改变旧链接。
- 第一条非空行可用 `# 标题`，作为目录和阅读页标题；省略时自动使用“第31章”等数字标题。标题下必须有正文。
- 为保持主稿的既有阅读表现，每个非空正文行显示为一段；不要为了编辑器视觉换行而手工把同一段拆成多行。整行 `【……】` 显示为场景标题。空行忽略，行首尾空白裁去，正文内容不改写。
- 章节是原文阅读接口，不解析档案元数据、粗体、表格、HTML 或图片。Markdown 标记会作为正文文本显示。章节草稿请以 `_` 开头命名，完成后再改为正式文件名；不要添加 `draft: true` 元数据。
- 删除章节会在下一次成功部署时移除目录入口和正文，旧地址显示未找到。至少保留一个非空章节。
- 章节目录为平铺的快速跳转窗口，不设分卷/分组。首页显示实际总章数与前六章入口，首章按钮指向实际第一条记录。

## 3. 六类档案接口

### 最简条目

以 `设定集/人物/personnel_11.md` 为例：

```markdown
# 档案名称

面向公众的介绍正文。首个普通段落会自动生成列表摘要。

## 相关记录

补充说明。
```

一个文件对应一条档案。按文件编号数值升序排列，允许跳号和超过 99 的编号；编号须为正整数，同栏目 01 和 001 视为重复。只扫描对应文件夹第一层 `.md`；`README.md`、下划线开头的文件会忽略，其他命名错误会报错。删除文件会移除条目。

默认**无图像、无图像占位、无档案字段侧栏**。可复制 `设定集/条目模板/` 中各栏目模板。模板带 `draft: true`，完成后须改为 `false` 或删除该行。

### 可选元数据和字段

```markdown
---
id: stable-record-name
summary: "列表中的短摘要"
kicker: "科研人员 · 公开档案"
status: "持续更新"
draft: false
---

# 档案名称

## 档案字段

- 身份 / 研究员
- 所属机构 / 广寒宫数据中心

## 正文

完整的公众介绍。
```

顶部元数据是受限的单行键值格式，**不是完整 YAML**。使用 `---` 开始和结束；不支持数组、嵌套对象、多行值。允许空行和以 `#` 开头的注释行。未知或重复字段会报错。

| 字段 | 用途与默认行为 |
|---|---|
| `id` | 可选，省略时为文件名去掉 `.md`；同栏目唯一，仅小写英文字母、数字、下划线、连字符，首字符须为字母或数字。决定 `#/栏目/id` 地址。迁移条目的旧 id 应保留。 |
| `title` | 可替代 `# 标题`；两者都有时以正文一级标题为准。 |
| `summary` | 列表与详情页摘要；省略或留空时取首个普通段落，去掉星号、反引号与换行后截取前 100 字，超长附省略号。 |
| `kicker` | 条目类别；默认“栏目名 · 公开档案”。 |
| `status` | 状态文案；默认“已收录”。 |
| `draft` | 只接受 `true` / `false`；true 时该文件不进入公开输出。 |
| `image` | 可选图片路径，详见第 6 节。 |
| `image_alt` | 图片说明；省略时使用档案标题，建议明确填写。 |
| `image_placeholder` | 只接受 `true` / `false`；仅明确规划但图片尚未制作时设 true。 |

文本值可以不加引号，也可以用单引号或 JSON 风格双引号包裹；双引号内部的双引号用 `\"` 转义，单引号内部的单引号写成两个单引号。布尔值不加引号。

`## 档案字段` 区域只写 `- 字段 / 内容`，斜线两侧保留空格；用 `## 正文` 或另一二级标题结束该区域。`## 正文` 是分隔标记，不显示在网页上。没有字段时不要保留空的字段区。

### 档案与关于我们的正文语法

支持普通段落、二至四级标题、`**粗体**`、`*斜体*`、行内代码、三反引号围栏代码块、单层有序/无序列表、引用、简单 Markdown 表格及 `https://`、`http://`、`#/` 链接。每段以空行分隔；不支持嵌套列表、任务列表、脚注、复杂嵌套行内样式。表格单元格内不要使用竖线，所有行列数须与表头一致。原始 HTML 会转义为文本，正文 `![图片](...)` 不会接入图片。

## 4. 纪年接口

编辑 `设定集/联邦大事年纪.md`，保持以下格式：

```markdown
---
2050 · 当年简概

详细纪年第一段。

详细纪年第二段。
---
2051 · 下一年简概

详细纪年。
---
```

也可使用 `## 2050年 · 当年简概`。年份须为四位数字，分隔符可用 `·` 或 `•`。构建按年份排序，年份重复、没有年度条目或某年正文为空会报错。空行和 `---` 分隔段落，首个年份之前的总标题忽略。纪年正文按文字呈现，保留段内换行，不使用六类档案的元数据或富文本渲染器。

界面以倾斜文件夹选择年份，标签显示年份与简概，点击展开年度正文；滚轮、键盘、滑杆和下拉选项均可切换。纪年不设图片接口。

## 5. 关于我们接口

唯一来源：`设定集/关于我们/about_us.md`。

```markdown
# 关于镜 / About Mirror

## 我们是什么

项目介绍。

## 技术概要

| 项目 | 说明 |
|---|---|
| 运营方 | 广寒宫数据中心 |

> Mirror 项目由广寒宫数据中心独立运营
```

使用一级标题和非空正文，不使用档案元数据。支持第 3 节所列正文语法；分节采用连续阅读排版，手机上表格在区域内横向滚动。关于我们目前无图片元数据接口。

## 6. 图片接口与默认规则

**用户没有明确要求配图时，所有新增条目默认纯文字，不添加图片或占位。** 人物、事件、地点、组织可以显式启用单张档案图；新闻、技术、纪年保持无图。

### 档案图片

将实际文件放入 `site/assets/`，在对应档案元数据中填写：

```yaml
image: assets/personnel_11.png
image_alt: "图中人物的姿态、环境与必要识别信息"
```

- 路径相对 `site/`，必须以 `assets/` 开头；不要写 `site/assets/`、`./assets/`、绝对路径或远程 URL。
- 支持 `.png`、`.jpg`、`.jpeg`、`.webp`、`.gif`、`.svg`、`.avif`，文件必须存在，路径与文件名大小写一致。
- 禁止 `..` 路径段、查询参数、锚点、反斜线、百分号、尖括号或引号。建议文件名使用英文、数字、下划线和连字符。
- 图像同时用于列表卡片和详情，`image_alt` 用作替代文本及图注。只有一个图像位；多图、正文插图和独立人物剪影布局尚无专用接口，需要另行实现。
- 已明确规划但暂未制作的图像，可仅写 `image_placeholder: true` 与 `image_alt`。同时提供 image 时显示真实图片。
- 不写 image 且不启用 image_placeholder 就是纯文字，单独写 image_alt 不会创建图像位。
- 新闻、技术在 `site/sections.json` 中配置 `mediaEnabled: false`；向这些栏目的条目添加有效 image 或 true 占位字段会停止构建。不能为了默认模板擅自重新开启。
- 老条目保留了已明确设置的占位。要改为纯文字，删除 image、image_placeholder 即可，可一并删除 image_alt。

### 封面与其他静态资产

首页封面固定读取根目录 `封面.png`，构建复制为 `dist/assets/cover.png`。更新封面请替换根目录文件；不要把档案图命名为 `site/assets/cover.png`，该位置在构建时会被封面覆盖。站点图标为 `site/favicon.svg`。`site/assets/` 的所有文件会随网站复制发布；不要在其中放置草稿正文或不应公开的文件。

章节、纪年、关于我们目前均无内容层图片接口。Markdown 正文图片语法不会自动显示。设计与资产制作约定另见 `视觉企划/00_视觉总纲.md`、`视觉企划/01_视觉策划书.md`。

## 7. 栏目扩展接口

`site/sections.json` 的数组顺序决定侧栏与首页栏目顺序。新增常规档案栏目时，在数组中增加一项，并建立目录：

```json
{
  "id": "objects",
  "number": "09",
  "title": "事物",
  "en": "OBJECTS",
  "intro": "公共档案中的器物与其他对象。",
  "sourceDir": "设定集/事物",
  "prefix": "objects",
  "mediaEnabled": false
}
```

对应文件为 `设定集/事物/objects_01.md`。id 须唯一并使用安全的英文路由名，不要占用 `read`、`chronology`、`about` 或其他已有 id。sourceDir 必须位于设定集内且实际存在，prefix 对应文件名前缀。number 是展示编号，排序以数组位置为准。mediaEnabled 为 false 表示栏目强制禁图；省略则允许显式配图，但条目仍默认无图。

纪年、关于我们是专用版式，不填写 sourceDir/prefix。首页的系统文案、封面介绍、页面布局与阅读界面文案仍在 `site/app.js`，站点外壳在 `site/index.html`，它们不是 Markdown 内容接口。不要误以为设定集内的任意 Markdown 都会自动发布。

## 8. 构建、发布与更新诊断

本地构建和解析测试只需要 Python 3.11 或以上，无第三方运行依赖：

```bash
python scripts/build_site.py
python -m unittest discover -s scripts -p 'test_*.py'
cd dist
python -m http.server 8000
```

浏览器访问 `http://localhost:8000/`。须预览构建后的 dist，直接打开 site/index.html 缺少生成的数据。

| 构建模块 | 输入与输出 |
|---|---|
| `scripts/chapters.py` | 章节 Markdown → 排序后的章节对象 |
| `scripts/catalogue.py` | 六类档案、关于我们 → `dist/data/catalogue.json` |
| `scripts/build_site.py` | 统筹构建，生成 `dist/data/manifest.json`、`dist/data/chapters/001.json` 等，以及 `dist/data/chronology.json` |
| `site/sections.json` | 生成 `dist/content.js` 中的栏目配置 |
| `site/`、`封面.png` | 页面、样式、脚本、资产复制到 dist |

`dist/` 每次先清空再重建，删除的章节/档案不会残留。不要编辑或提交 dist、生成的 content.js、JSON 数据来维护正文；也不要恢复旧版手写 `site/content.js`。章节路由保留 `#/read/1` 等数字地址，与生成 JSON 的三位文件名不同。

`.github/workflows/pages.yml` 在 `main` 的 `各章节/**`、`设定集/**`、`site/**`、`scripts/**`、`封面.png` 或工作流自身变动时运行；pull request 只检查，不部署；也可手动运行 **Publish Mirror archive**。修改历史合并稿或 README 本身不会触发正文更新。

CI 会运行解析测试、纪年交互、档案/关于我们检查、章节目录与正文更新检查，再部署到 GitHub Pages。桌面/手机截图保存在名为 `chronology-ui` 的构件中，该名称沿用早期工作流，现包含其他页面。浏览器测试使用 Playwright，安装方法见工作流；生产站点不依赖 Playwright。

网站地址：<https://tempaofc-lang.github.io/project-Melqu-ades-Ballad-/>

Pages 发布来源应设为 **GitHub Actions**。推送之后须等待对应提交的 build、deploy 均成功，再刷新或离开当前栏目后重新进入。首页章数、章节目录、正文、六栏档案、关于我们和纪年均在进入时重新核对数据；不会在阅读中途自动替换正文。栏目配置或脚本改动后请整页刷新。

更新未出现时依次检查：提交是否在 main；编辑的是不是上表中的唯一来源；文件名、目录、编号、草稿标记是否正确；对应 Actions 是否触发并部署成功；最后刷新页面。失败构建不会覆盖线上旧版本，先按日志中的文件路径修复错误，不要直接改生成文件。

## 9. 给维护 Agent 的操作约定

1. 先读取当前远程版本与相关源文件，保留作者新推送的正文、旧 id 和既有视觉约定。
2. 修改内容只操作对应唯一来源；章节原文不改写，公众档案文案按 2087 年世界内视角撰写。
3. 新增档案不默认配图；六类档案元数据不能套用到章节、纪年或关于我们。
4. 章节数量、编号和栏目条目数量不可硬编码，目录与相邻项从构建结果推导。
5. 构建、检查通过后再部署，说明本次改动及验证结果；出现格式错误应修正源文件，不应削弱校验以掩盖错误。
