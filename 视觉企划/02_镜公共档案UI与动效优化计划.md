# 镜公共档案 · UI 与动效优化计划

日期：2026-09-19  
基线提交：`885ba83`  
对象：当前 GitHub Pages 静态站点的首页、章节阅读、六类档案、纪年与关于页。

### 2026-09-20 实施记录

按后续确认的范围，已在本地实现以下内容：

- 全站检索：按需加载本次构建的公开索引，标题优先，正文匹配片段高亮，章节结果定位段落，键盘选择与失败重试。
- 阅读续接：首页和章节目录提供续读入口，按段落文本恢复阅读位置，正文变动时重定位或提示返回章首；存储不可用时可继续正常阅读。
- 轻量开屏：首页首次标签页会话播放约 5.4 秒的序列：竖线、横线、圆环、圆心，再逐字显示名称和中英文字幕，最后淡出，可跳过；直达章节及减少动态效果模式跳过。
- 微交互：导航淡入、卡片箭头与按钮反馈、筛选计数、复制链接确认；同时完成手机菜单的关闭入口、遮罩、焦点循环与归位，并扩大阅读和纪年按钮的触控区域。

已通过构建、16 项单元测试和四个 Playwright 浏览器检查；新增体验覆盖桌面、平板、手机尺寸。全站排版统一与档案占位图紧凑版式仍为后续优化项。双版本核查暂不进入实施范围。

## 1. 目标与设计方向

让读者更快进入正文和档案，让查阅、切换、展开记录的状态更清楚。动效沿用“档案被选择、展开、归位”的物理逻辑，服务于操作反馈和页面连续性。网站继续遵循[视觉总纲](00_视觉总纲.md)的白灰纸面、低饱和、清晰结构与机构语境；章节正文以安静阅读为先。

当前站点用原生 HTML、CSS 和 JavaScript 即可完成这轮优化。沿用现有 Python 构建和 GitHub Pages 流程，保留章节、档案、纪年及关于页的内容接口和 URL。明确设置的 `image_placeholder` 仍表示影像待接入；调整的是列表中的呈现权重。

## 2. 评审基线

- `python scripts/build_site.py` 成功。
- 仓库现有的纪年、章节、档案 Playwright 浏览器脚本均通过。
- 额外检查桌面 `1440×900`、手机 `390×844` 的 14 次代表页面访问：首页、章节目录与正文、人物列表与详情、纪年、关于页。未发现页面脚本错误、请求错误或页面横向溢出。
- 已有可取之处：白灰档案语言与宋体阅读区吻合；栏目层级明确；纪年文件夹是独有的交互意象；站点已有 `prefers-reduced-motion` 分支。

| 优先级 | 发现 | 对读者的影响 | 主要位置 |
|---|---|---|---|
| P1 | 手机首页先出现大幅封面，首章入口落在封面与介绍之后 | 首屏看得到作品，却难以立即开始阅读 | `site/app.js`、`site/styles.css` |
| P1 | 人物等档案列表中，待接入影像占位占据卡片上半部 | 手机上一屏只能扫到很少的条目标题 | `site/app.js`、`site/styles.css` |
| P1 | 手机侧栏关闭时仍可进入键盘焦点；打开后缺少遮罩、外部点击关闭与焦点管理 | 键盘和触屏使用时可能迷失在菜单与正文之间 | `site/index.html`、`site/app.js`、`site/styles.css` |
| P2 | 换页重建 `main` 后未把焦点送到新内容；整个 `main` 设置了 `aria-live` | 辅助技术可能收到冗长播报，换页位置不明确 | `site/index.html`、`site/app.js` |
| P2 | 手机字号按钮约 `35×30px`，纪年切换按钮约 `36×36px`，部分文字链接点击区域更小 | 触控操作不够从容 | `site/styles.css`、`site/chronology.css` |

## 3. 实施顺序

### 阶段一：入口、列表与操作可达性

1. 在手机首页作品介绍的前段提供直接进入首章的链接或按钮，让读者在看到封面前即可开始阅读；桌面保留现有封面和作品信息的并列关系。
2. 为带 `image_placeholder` 且无真实图片的条目提供紧凑列表版式：优先显示标题、摘要、状态；将“影像待接入”缩为清楚但不抢眼的标签。详情页仍可显示完整占位语义。
3. 完成手机菜单的开闭体验：打开时有遮罩和明确关闭入口；可通过遮罩、Escape 和导航选择关闭；关闭时侧栏不可进入焦点；打开时焦点进入菜单，关闭后回到触发按钮。检查页面滚动和浏览器返回。
4. 放大独立按钮和导航链接的可操作区域，优先覆盖菜单、阅读字号、纪年切换与卡片返回入口。维持清晰的焦点样式，并在手机上核对字号较小的状态文字。

**验收：** 390px 宽首屏能找到首章入口；档案首张卡片在首屏即可读到标题；菜单支持完整键盘开闭；主要独立触控目标达到约 `44×44px` 的设计尺寸且没有重叠。

### 阶段二：全站排版与导航反馈

1. 整理字号、行高、间距、边界线和卡片状态的 CSS 变量，使首页、目录、详情和阅读页遵循同一套层级；保留中文正文的衬线字与界面标签的无衬线字分工。
2. 换页后把焦点送到新页面标题或主内容起点，使用简短的独立状态播报，避免把整章正文作为一次动态更新朗读。
3. 检查搜索无结果、档案无图片、长标题、长摘要、纪年长年份说明等状态；让信息密度增加时仍保持可扫描性。

**验收：** 键盘换页后可从新页面标题继续浏览；标题与正文无裁切；列表的默认、悬停、焦点和筛选状态可辨认；手机和桌面保持一致的阅读层级。

### 阶段三：有目的的动效

**主场景：纪年卷宗。** 保留“选择文件夹 → 展开年度记录 → 返回原年份”的空间关系，微调文件夹选择和对话框开合，使每一步都能说明当前所处位置。点击、键盘、滚轮、滑杆和下拉选择应得到一致的状态反馈。

**全站辅助动效：**

- 导航切换：缩短当前遮罩等待时间，让新页的出现与导航状态同步；连续快速切换不会闪烁或显示过期内容。
- 档案卡片与按钮：用边框、背景、轻微位移或箭头变化表达可操作性，焦点状态与悬停状态同样清楚。
- 手机侧栏：遮罩和面板同步进入、退出；焦点行为由状态控制，而非动画结束时机控制。
- 章节阅读：保留静止正文与阅读进度反馈，不对段落逐个入场。

以 CSS 动画和现有 JavaScript 状态管理实现，常规反馈以约 `120–240ms` 为目标，卷宗开合可略长。优先动画化 `transform` 与 `opacity`；逐项检查 `prefers-reduced-motion`，减少空间移动，同时保留必要的颜色、边框或状态文字反馈。动效中途再次点击或快速切换时，界面应能立即响应。

**验收：** 常规导航没有可感知的额外等待；纪年状态切换前后位置明确；减少动态效果模式仍可辨认选择和展开状态；章节长文滚动保持流畅。

### 阶段四：回归核查与交付

1. 运行构建、单元测试及仓库现有的三个 Playwright 浏览器脚本。
2. 在 `1440×900`、`768×1024`、`390×844` 检查首页、阅读、档案列表/详情、纪年与关于页；覆盖正常动效与减少动态效果两种偏好。
3. 用键盘走通手机菜单、章节导航、筛选、纪年卷宗与对话框；检查焦点归位、浏览器前进/后退、快速重复点击、无结果与加载失败状态。
4. 对比优化前后的截图，检查横向溢出、遮挡、文字可读性及控制台错误。仅在发现具体回归时补充测试。

**交付标准：** 构建与现有浏览器检查通过；没有新增页面错误或横向溢出；五项已记录问题得到验证；视觉表现符合现有视觉总纲。
