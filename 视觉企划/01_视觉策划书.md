# 梅歌视觉企划 · 01 视觉策划书

> 本文件承接 `00_视觉总纲.md`。总纲规定风格边界；本策划书规定如何将其落实为 GitHub Pages 可使用、可检索、可追溯的视觉档案系统。
>
> **总定位：** 网站不是“为小说制作的宣传页”，而是从 2087 年留存下来的、多机构并行维护的公共档案入口。每一张图都必须有明确的生产者、用途、时间、权限与信息立场。

---

## 一、视觉叙事总原则

### 1. 真实机构原则

每项资产首先回答：**是谁做的、给谁看、用来做什么。**

- 广寒宫工程图：维护、交接、故障排查；
- 世界联邦资料卡：公共通报、制度说明；
- 轮回派材料：传教、情绪安抚、行为塑形；
- 火种材料：低成本复制、隐蔽传播、信息留存。

“好看”不是孤立目标；可信的行政、工程与档案逻辑优先。

### 2. 非全知原则

不使用上帝视角图解“覆盖”的真相。每份材料只呈现其机构在当时可知的内容；不确定处通过版本、注记、缺失字段、权限限制与来源冲突呈现。

### 3. 物证优先原则

不以炫技特效制造“未来感”，而以编号、磨损、签名、温湿度、校验码、维修痕迹、文档修订记录制造可信度。

### 4. 版本冲突原则

“镜”相关资产允许且必须保留差异：事件前版本、观察分支、人工核查说明并存。红／蓝双色仅服务于这一语境。

## 二、网站视觉信息架构

| 层级 | 站内功能 | 视觉形态 |
|---|---|---|
| 世界入口 | 让访客理解 2087 年的社会与事件 | 世界地图、时间线、公共新闻摘要 |
| 机构档案 | 建立组织的制度感与立场 | 机构页、徽记、流程图、制式文件 |
| 人物档案 | 通过岗位与行动认识角色 | 剪影、证件照式头像、工作记录、关系索引 |
| 事件档案 | 让事件成为可检索、可交叉验证的记录 | 时间戳、地点、来源、状态、关联证物 |
| 地点与技术 | 把世界落到可运行的空间与设备 | 轴测图、剖面图、维护卡、操作界面 |
| 镜／版本核查 | 作为网站的叙事核心机制 | 双版本对照、差异高亮、人工确认区 |

## 五、资料卡统一字段

所有角色、地点、技术、事件采用同一套档案元数据，保证网站是一个系统，而非图集。

| 字段 | 示例 |
|---|---|
| 档案编号 | `EV-2087-JRS-01` |
| 标题 | 耶路撒冷强遗忘事件 |
| 归档机构 | 广寒宫运营委员会 |
| 记录时间 | `2087-██-██ 12:00–17:00` |
| 状态 | 已核查／观察中／来源冲突／权限受限 |
| 版本 | 事件前接收版本／观察分支 |
| 可信来源 | 月球本地快照、纸质记录、人工证言 |
| 关联条目 | 人物、地点、技术、事件 |
| 备注 | 不替读者下结论，只标注差异 |

## 六、关键风格补充

- **人物剪影**：低照度、真实工作空间；避免角色立绘与姿势化构图。
- **事件档案**：尽量用证据组合代替单张插画，例如照片、波形、地图、修订记录、时间戳并置。
- **地点概念图**：以轴测、剖切、工程视图为主；人物只作为尺度参考。
- **轮回派材料**：不做邪教视觉奇观。它应温和、整洁、容易被接受；暴力只在档案缺失、被改写的记录中显影。
- **普罗米修斯与火种**：不英雄化；前者是严谨而失败的观测，后者是低成本、易损毁的抵抗。
- **站点初始状态**：建议设为“广寒宫本地档案访问端”，而不是中立百科；这样“版本偏差”“人工核查”“暂不执行”自然成为交互与叙事的一部分。

## 七、制作与校验要求

1. 所有资产生产前，先核对 `00_视觉总纲.md` 的色板、字体、线宽、符号与禁忌。
2. 角色、地点、技术与事件卡均须绑定正文与设定集词条，避免视觉资产脱离文本。
3. 不得使用游戏化 UI、霓虹泛滥、强逆光、镜头光晕或对“它”的定性断言。
4. 每项资产完成后均应补充：版本号、生成／绘制日期、机构归属、来源与校验状态。
5. 优先完成 A 批世界锚点，再启动 B 批人物资产。
